# v3.1 / build 84：导入与弹层修复

用户真机反馈：本地选择 supjav.webox.js 后无法导入；导入弹层留白过大、两处选择文件入口重复，系统分段控件有重影。

## 已修改

- UIDocumentPicker 使用 asCopy:true。导入 App 获得复制文件后读取，不直接长期依赖第三方文件提供器的短期访问 URL。
- 保留 security-scoped 访问，使用 NSFileCoordinator 协调读取 iCloud/第三方文件提供器，读取失败区分“提供器错误”和“文件尚未下载”。
- 文件选择回调后稍后开始导入，等文件选择器结束收起。取消选择恢复按钮状态。
- 导入阶段使用只读元数据检查模式；声明 DOM 能力的有效 WeBox.define 脚本可以先保存，但会提示当前运行时未支持 DOM。没有假装该能力已实现。正常浏览仍使用实际能力检查。
- JavaScript 注册异常被捕获并原样传递；不再一律写“缺少有效元数据”。有语法错误、抛出异常会明确报错。
- 支持带 UTF-8 BOM 的脚本。
- 结果提示移到操作按钮附近；失败会弹出具体错误，Documents/last-import-result.json 留存文件名/成功数/错误原因，便于真机定位。
- 自适应高度导入弹层，随链接/文件模式、类型展开、名称图标展开和错误结果更新高度，保留滚动与向上展开。
- 只保留底部一个选择文件按钮；上方变成说明文字，不再两个重复按钮。
- 分段按钮改为自绘滑块，消除 UISegmentedControl 多层背景重影。

## 不能据截图确认的事项

截图里只有 supjav.webox.js 文件名（约40KB），本会话附件没有该脚本本体。不能据此确认该文件导入失败的唯一根因，也不能说已实测兼容这份脚本。需要原始文件进一步验证；不可用另一个同名网上文件冒充用户原始文件。

## 运行验证

沿用原有 demo列表/搜索/播放地址、持久化、HTTP、并发HTTP测试，新增：
- 声明 requires:['dom'] 的合成 WeBox.define 脚本：导入保存成功、给出运行能力提示。
- 明确抛错的脚本：拒绝导入并包含 fixture-specific-error。
- 调用与 UIDocumentPicker 相同 delegate 方法后等待异步导入：来源必须保存，status必须有成功反馈。
- 实际模拟器分别生成链接模式与本地文件模式截图。

测试不替代真实 iCloud 文件提供器和用户原始脚本的真机验证。
